Uzumaki for Arch Linux

Install from the AUR, prebuilt or from source. It updates with your system. Wayland and X11.

macOSArch LinuxAppImage · any distroWindows

Beta Version 0.2.0 is out. Release notes and checksums are on the release page.

What you need

  • Arch Linux on x86_64, with an AUR helper such as yay or paru.
  • A GPU with a Vulkan driver: vulkan-radeon, vulkan-intel or nvidia-utils.
  • An Apple Music subscription, to stream. Your own music files play without one.

Wayland and X11 both work. On X11 you also need libxkbcommon-x11: Uzumaki loads it at start-up and stops without it.

Install

There are two packages. For a quick install, use uzumaki-bin: it takes the prebuilt AppImage and needs no build. Use your AUR helper:

$ yay -S uzumaki-bin $ paru -S uzumaki-bin

If you prefer to build it yourself, install uzumaki, which builds from source:

$ yay -S uzumaki $ paru -S uzumaki

Install only one of them: the two packages conflict with each other.

Then start Uzumaki from your app menu and sign in to Apple Music from the banner. The Widevine module that plays the music downloads by itself on that first start.

What it builds

This section is about the uzumaki package. uzumaki-bin builds nothing: it installs the release’s prebuilt AppImage.

The uzumaki package builds Uzumaki from the release’s source on your machine. The first build takes a few minutes.

  • It compiles the app and the uzu command with Rust. Build tools: rust, npm, git and pkgconf.
  • It fetches castLabs Electron with npm (about 290 MB). This is the hidden player that plays Apple Music.
  • It installs to /usr/lib/uzumaki, with uzumaki and uzu in /usr/bin, plus the app-menu entry, icons and licence.

Widevine isn’t part of the package. It downloads from Google on first use.

Updates

Update Uzumaki with the rest of your system. Uzumaki shows a notice when a new version is out, and tells you to use your package manager.

$ yay -Syu

Uninstall

$ sudo pacman -Rns uzumaki-bin

Use uzumaki instead of uzumaki-bin if that is the one you installed.

Your login, settings and caches stay in ~/.config/uzumaki and ~/.cache/uzumaki. Delete those two folders to forget everything.

Settings → App icon works with the package too. Uzumaki never writes to /usr: for Light or Coral it puts its own icons and a copy of the app-menu entry in ~/.local/share, and choosing Dark again removes them.
